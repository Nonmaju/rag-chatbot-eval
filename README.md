# 가천대 입학 Agentic RAG 챗봇

가천대학교 2027학년도 입학 문서(HWP 1개, PDF 4개)만 근거로 답변하는 **Agentic RAG 챗봇**입니다.
부트캠프 "생성형 AI 활용" 중간평가 과제로 3시간 안에 구현했고, 개선을 **한 번에 하나씩** 적용하고 같은 평가셋으로 재측정하며 실험 기록을 남겼습니다.

> 문서에 없는 내용은 답하지 않습니다. 웹 검색·외부 자료는 사용하지 않고, 평가 질문/정답은 코드에 넣지 않았습니다.

## 핵심 결과

### 실제 채점 결과 (비공개 평가 질문 50개)

| 항목 | 점수 |
|---|---|
| **총점** | **87.9 / 100** |
| 정확성 | 70.4 / 80 (50문항 중 44문항 정답) |
| 응답 시간 | 17.5 / 20 (평균 3.35초, 5초 초과 2문항, 최대 6.1초) |

- 평가는 문항당 3회 실행하고 3회 중 2회 이상 정답이면 정답으로 인정했습니다. 시간은 3회 평균입니다.
- 제출한 구성: gpt-5.4-mini + text-embedding-3-large, 청크 800/100, 벡터 4 + BM25 4 하이브리드, HWP 표 정제, 출처 접두어, 면접 일정표 변환.

### 개발 중 자체 평가 (직접 만든 질문 54개)

직접 만든 질문셋 54개(정답은 문서에서 하나씩 확인)로 평가·검증했고, 문항당 2회 반복 측정한 결과입니다. 정답 여부는 LLM이 판정했습니다.

| 지표 | 값 |
|---|---|
| 정확도 | 0.926 (환산 약 92.6점) |
| 평균 응답 시간 | 2.33초 (최대 3.7초, 오류 0건) |

실제 채점(정확도 0.88, 87.9점)이 자체 평가보다 낮았습니다. 자체 질문셋이 비공개 질문의 분포(예: 존재하지 않는 연도를 묻는 질문, 여러 조건을 묻는 질문)를 충분히 반영하지 못했기 때문으로 봅니다. [추론]

#### 틀린 6문항의 유형 (채점표의 학생 응답 기준 분석)

| 유형 | 문항 | 내용 |
|---|---|---|
| 문서에 없는 연도를 묻는 질문 | 2개 | "2028학년도" 원서접수·모집인원을 묻는데 2027학년도 값으로 답함 (3회 중 한 번만 "2028학년도는 확인할 수 없다"고 정정) |
| 표에서 값 조회 | 2개 | 재외국민 모집인원 표의 특정 학과(컴퓨터공학과 최대모집 가능인원, 간호학과)에서 3회 모두 같은 오답 또는 검색 실패 |
| 그 밖 (원인 미확인) | 2개 | 지역의사선발 의예과 수능최저(탐구 두 과목 평균 적용 여부), 수시 변경사항(신설 학과와 개명). 여러 조건을 묻는 질문 약 20개 중 오답은 이 2개(약 10%)라 전체 오답률(12%)과 비슷해, 이 유형 자체가 약점이라고 보기는 어려움 |

- 시간은 효과가 컸습니다. 50문항 중 48문항이 평균 5초 이하라 시간 점수 20점 중 17.5점을 받았습니다.
- 3회 중 일부만 정답인 문항이 9개 있었습니다(Q04, Q07, Q12, Q17, Q24, Q38, Q39, Q42, Q46). 같은 질문에도 결과가 달라지는 불안정성이 있습니다.

#### 자체 질문셋 vs 실제 평가 질문 비교

질문 유형은 키워드로 센 근사치입니다.

| | 자체 54문항 | 실제 50문항 |
|---|---|---|
| 평균 질문 길이 | 35자 | 69자 (최대 131자) |
| 여러 항목·조건을 묻는 질문 | 약 9% | 약 40% |
| 계산·변환형 | 약 15% | 약 36% |
| 문서에 없는 정보·함정형 | 0개 | 명확한 것 8개 (모호한 것까지 10~12개) |
| 문서 간 결합 질문 | 0개 | 4개 이상 |
| 02 지역의사 질문 수 | 4개 | 12개 |

- **잘 맞았던 판단**: 면접 일정표 변환에 투자한 결과, 실제 평가의 면접 일정 질문이 모두 정답이었습니다. 지역의사 질문(7문항)도 자체 질문이 4개뿐이었는데 전부 정답이었고, 계산·변환형 질문에서도 오답이 없었습니다.
- **놓친 약점 1: 틀린 전제의 질문.** 경쟁률·합격선·개인 정보처럼 문서에 아예 없는 정보는 6개가 "확인할 수 없다"고 잘 답했습니다. 반면 연도만 다른 질문(2028학년도) 2개는 2027학년도 값으로 답해 틀렸습니다. 거의 맞는 문서가 있으면 그 내용으로 답해 버리는 문제입니다.
- **놓친 약점 2: 표의 행 조회.** 자체 재외국민 표 질문은 2개 학과만 확인해 모두 통과했지만, 실제는 다른 학과(컴퓨터공학과, 간호학과)를 물었고 둘 다 틀렸습니다.
- **질문셋을 다시 만든다면**: 함정형 10개 이상, 표의 다양한 행 조회, 02 지역의사 질문 확대, 문서 간 결합·계산형, 60자 안팎의 긴 질문, 평가 때 "3회 중 2회" 규칙 적용.
- 시간은 실제 평균 3.35초로 자체 측정(2.3초)보다 느렸습니다. 평가는 3회 평균이고 환경이 달라서로 보이며, 자체 측정 시간을 그대로 믿으면 낙관적입니다.

## 구조

```
HWP/PDF 로드 → 정제 → 분할 → 임베딩(Chroma) ┐
                                            ├→ 하이브리드 검색 → rag_tool → create_agent → 답변
                          Kiwi 형태소 BM25 ┘
```

- **하이브리드 검색**: 벡터 검색(코사인)과 한국어 형태소 BM25를 합쳐 중복 제거
- **Agentic RAG**: 에이전트가 검색 결과가 부족하면 질의어를 바꿔 재검색 (최대 3회)
- **견고성**: LLM 타임아웃·재시도, 오류 시 검색+단일 생성 폴백, 예외 없이 항상 문자열 반환
- **평가 도구**: 질문당 반복 실행, 항상 틀림/왔다갔다(flaky) 구분, 채점 공식(정답 + 응답 시간 점수) 계산

## 기술적으로 해결한 문제

| 문제 | 원인 | 해결 |
|---|---|---|
| 배포용 HWP가 로드 실패 | 기본 로더가 배포용 문서를 지원하지 않음 | `pyhwp` 백엔드 지정 |
| 재외국민 표 질문 오답 | HWP 표에 `[merged:R6C1]` 같은 파싱 잡음 7.9만 자 | 잡음 제거(→ 1.9만 자), 정확도 0.844 → 0.906 |
| 면접 일정표 질문 전부 오답 | ★ 행렬 표를 텍스트로 뽑으면 어느 날짜 열인지 사라짐 | 표를 헤더와 합쳐 "학과: 날짜 오전/오후" 줄로 변환 (표의 값만 사용) |
| 변환 후 일부 질문 악화 | 짧은 행 청크 88개가 원본 표 청크를 검색에서 밀어냄 | 행을 ~700자씩 묶어 8개로 축소 |
| ★이 없는 날짜가 사라짐 | 행 단위 변환 시 표 헤더의 날짜 정보 손실 | 묶음 상단에 헤더 날짜를 원문 그대로 포함 |

## 실험 기록

한 번에 하나씩 바꾸고 같은 질문셋으로 비교했습니다. (정확도는 해당 시점의 질문 수 기준이라 행 간 직접 비교는 참고용입니다.)

| 실험 | 변경 | 결과 | 채택 |
|---|---|---|---|
| 기준선 | 800/100 청크, k=4 + BM25 4 | 0.844 (32문항) | 기준 |
| HWP 표 정제 | 파싱 잡음 제거 | 0.906 | O |
| 출처 접두어 | `[출처: 파일 p.n]` 부착 | 단독 0.812, 정제와 함께 0.969 | O (정제와 함께) |
| 검색량 증가 | k, bm25_k를 6으로 | 정확도 동일, +0.3초 | X |
| 전형 제목 부착 | 소속 전형 제목을 청크에 부착 | 0.927 → 0.927 (변화 없음) | X |
| 일정표 변환 | ★ 표 → 학과별 날짜 줄 (v3) | 0.926 (54문항) | O |
| 구조 기반 청킹 | 소제목 기준 분할 | 0.917, 일부 문항 개선·일부 악화 | X |

실험을 하며 얻은 점:
- 1회 측정은 문항이 1~4개씩 뒤집히는 잡음이 있어 2회 반복 측정으로 바꿨습니다. (질문 54개에서 1문항 ≈ 1.9%p)
- 정확도뿐 아니라 응답 시간(5초 기준 점수)을 함께 봤고, 검색량을 늘리는 개선은 시간만 늘어 기각했습니다.
- 답변이 맞는데 판정 모델이 오답 처리하는 경우를 발견해 판정 프롬프트를 엄격하게 고치고 판정 근거를 출력하게 했습니다.

## 남은 한계

- **존재하지 않는 연도·조건을 묻는 질문**: 질문의 전제(예: 2028학년도)가 문서에 없어도 2027학년도 값으로 답하는 경우가 있음. 프롬프트에서 질문의 연도·전형이 문서와 일치하는지 먼저 확인하도록 해야 함
- **표 값 조회**: 표를 평문으로 추출하는 PDF 문서는 표 구조를 완전히 복원하지 못함 (표 추출 기반 직렬화는 면접 일정표에만 적용). 재외국민 표의 학과별 값 조회에서 실제 채점 오답 발생
- **여러 조건을 묻는 질문**: 한 질문에 여러 항목을 묻는 경우 항목별로 나눠 검색하지 못함 (`prompt_v2`는 코드만 있고 미측정)
- **3회 중 일부만 정답**인 문항이 있어 결과가 불안정함
- 개발용 평가셋(54문항)이 실제 출제 분포를 충분히 반영하지 못함 (자체 정확도 0.926 vs 실제 채점 0.88)

## 실행 방법 (Google Colab)

1. `dataset`(HWP/PDF 5개)을 `/content/dataset/`에 업로드
2. Colab 보안 비밀에 `OPENAI_API_KEY` 등록
3. `submission_rag_midterm.ipynb`를 위에서부터 실행
4. 질문 JSON을 `/content/questions.json`에 두면 마지막 셀이 답변을 출력하고 `answers.json`으로 저장

개발용 노트북에서는 `CFG` 플래그(`interview_rows`, `struct_chunk` 등)를 바꾸고 `run_eval("이름", repeats=2)`로 측정합니다.
