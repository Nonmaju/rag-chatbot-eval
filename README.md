# 가천대 입학 Agentic RAG 챗봇 (생성형AI활용 중간평가)

HWP/PDF 5개 문서만 근거로 답변하는 Agentic RAG. LangChain + Chroma + Kiwi BM25 + `create_agent(rag_tool)`.

## 채점 (문항 50개)
- 정답 1.6점 (부분점수 없음) + 시간점수: 5초 이하 0.4, 초과 1초당 -0.08 (10초 이상 0), 20초 초과/오류 0점
- 시간 = 질문 임베딩 + 검색 + 생성 (파싱/인덱싱 제외)
- 웹검색/외부자료/질문·정답 사전등록 시 전체 0점. 제출 전 API 키 제거

## 금지 / 허용 (절대 어기지 말 것)
- 금지: 웹 검색/크롤링/외부 사이트 조회, 제공 문서 외 자료 DB 투입, 질문·정답 사전등록, **데이터 자체의 조작(문서에 없는 내용 추가·변조, 정답 삽입)**, LLM 사전지식으로만 답변
- 허용: 로드 후 전처리(정제·정규화·메타데이터/출처 부착 등 원문 의미를 바꾸지 않는 것), 키워드(BM25) 검색, 파싱/임베딩 API, 답변 생성 LLM API, 분할(chunking), Vector DB 검색
- 지켜야 할 것: 제출 전 API 키 제거, 파일명 `학번_이름.ipynb`

## 실험 계획 (한 번에 하나, 같은 dev_questions.csv 32문항)
1. [완료] baseline / `clean_hwp` / `source_prefix` 2x2 -> 둘 다 켠 구성이 최고
2. [진행] `section_prefix`: 청크에 소속 전형 제목 부착 (문서 자체의 'OO 전형' 제목 줄 사용)
3. [완료·코랩 확인 대기] 견고성 패치(타임아웃/재시도/폴백, `.content` 리스트 처리, 재귀 glob, 로드 경고, 버전 출력). 정확도 변화 없어야 함, `fails` 열로 오류 경로 확인
4. [코랩 확인함, 개선판 대기] `interview_rows`: 05 면접일정표(★ 행렬) 88행을 "학과 | 날짜 오전/오후"로 풀어쓴 청크 추가 (평문 추출로는 날짜 열을 알 수 없음). dev 54문항(05·01 질문 13개 추가)
   - 54문항 결과: robust(견고성 패치) acc 0.815 / 2.26s / fails 0 / max 3.4s -> 05 학과별 날짜 7문항 전부 오답(예상대로), 01 재외국민 6문항 전부 정답
   - interview_rows v1(학과 1행=1청크, 88개) acc 0.833: 05 학과별 7문항 전부 정답 / 그러나 #15 #17 #19 면접 전반 질문이 오답(행 청크가 원본 표 청크를 밀어냄), #21 #32 #38 #40은 잡음 의심
   - v2: 행을 ~700자씩 묶어 8청크로 축소(지역균형 6개 학과가 한 청크). 코랩 재측정 필요
   - v2 결과 (repeats=2, 54문항): acc 0.870 / 2.03s / max 3.1s / est 87.0 / always_wrong 5(#14 #16 #36 #39 #41) / flaky 4(#15 #17 #32 #38). 05 학과별 질문 대부분 정답
   - v2 결함: 지역균형 표의 12월 7일(월) 열에 ★이 0개 -> 행으로 풀면 그 날짜가 사라져 #15 #16 #17("며칠에 실시") 오답. v3: 묶음 맨 위에 표 헤더의 날짜/구분 값을 그대로 포함
   - 측정 잡음: 같은 설정도 1~4문항 뒤집힘 -> run_eval(repeats=2)로 always_wrong/flaky 구분
5. [코드 완료, 코랩 대기] `struct_chunk`: 문서 자체의 소제목 줄(전형방법/지원자격/전형일정/수능최저학력기준/선발원칙/제출서류)에서 먼저 자르고 1200/100 재분할, 접두어에 `| 논술 전형 > 지원자격`. 로컬 BM25 순위(대상 청크): #39 8->1, #36 2->1, #32 2->1, #14 13->3, 학생부우수자 지원자격 8->1, 지역균형 모집인원 2->3
6. 이후: 프롬프트 보강, `doc` 필터 인자
6. 이후: 시간 여유(약 3초)를 정확도에 사용 - k / bm25_k 증가, 표 파싱 개선(PDF), 모델 변경 순으로 하나씩
